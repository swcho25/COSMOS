# 근거를 먼저 판독하는 뉴스 선별기 실험

2026-09-17 사용자가 빠른 뉴스 선별기 학습·검증(1번)을 계속하도록 요청했다.
이 작업은 전체 후보 선별, 지식그래프 생성, 기업 감성, GNN 재학습, 서비스 적재를 포함하지 않는다.
기존 GNN 번들, 선별기 실험과 학습 결과는 보존한다. 예약 알림은 만들지 않는다.

## 기존 실험에서 확인한 원인

기존 B의 개발용 LLM 판정 일치는 163/256(63.67%)이었다. 이는 사람 정답 정확도가 아니다.
오류 93건 중 87건이 규칙 처리보다 LLM 의미 판정 구간에 있었다. 기업명 규칙 분리만으로 해결된다고 단정할 수 없다.
보류 675개 중 334개가 공식 이름 문자열 부재 규칙에서 생겼고, 명확한 실적·인수·제품 채택 기사에도 잘못된 보류가 있었다.
반대로 단순 가격 나열을 LLM이 채택한 사례도 확인했다. 교사와의 불일치를 모두 학생의 오답으로 간주하지 않는다.
두 후보 모두 후반 학습 손실은 줄고 개발 손실은 늘어 단순 학습 횟수 증가는 선택하지 않았다.

진단은 `artifacts/kg_cascade_v3_diagnosis_20260917_v1/label_audit.md`와 `model_audit.md`에 있다.
노출된 TRAIN/DEV만 사용했고 실제 CAL/TEST 내용은 열람하지 않았다.

## 변경 사항

- `kg_target_aliases.py`: 기존 NER 사전에서 원문에 매칭된 기업 이름만 전달한다. 제품·산업·그룹·ticker-only 이름과 회사 간 충돌은 제외한다.
  이름 후보는 동일 법인·당시 사명·사업 관계의 증명이 아니다. 동명이인이나 스포츠팀은 문맥으로 판단한다.
- `kg_reasoned_teacher.py`: 기사 전체를 손실 없이 구간 ID와 함께 Qwen에 주고, 경제 경로·근거 ID·판정 순서로 생성한다.
  첫 개발 실행에서 의미상 맞는 출력도 임의의 근거 3개 상한과 제외 판정의 필수 인용 조건 때문에 실행 불가로 처리됐다.
- `kg_reasoned_teacher_v2.py`: 첫 구현은 보존하고 출력 계약만 수정한다. 근거 ID는 유효하고 중복이 없어야 하며, 채택에는 최소 1개가 필요하다.
  제외·보류는 근거 부재를 설명할 수 있으므로 빈 ID 배열을 허용한다. 모든 판정은 비어 있지 않은 이유가 필요하다.
  존재하지 않는 ID나 변형된 원문은 허용하지 않는다. 처리 실패는 의미상 보류와 분리한다.
- `kg_reasoned_teacher_v3.py`: 사건 주체(target/other/uncertain)와 사건 종류를 먼저 판정하고 코드로 채택·제외·보류를 결합한다.
  단순 주가 중계, 과거 직장 소개와 실제 사업 사건을 구분한다. 그룹·현지 운영사를 자동으로 같은 법인이라고 간주하지 않는다.
  원문에 대상 이름이나 허용 별칭이 전혀 없는 채택은 보류로 돌리고 원래 판정과 이유를 남긴다.
  이 보호 규칙이나 인용 ID의 유효성이 경제적 판단의 정확성을 입증하지는 않는다.
- `kg_reasoned_student.py`: 기존 B 구조에 같은 이름 후보를 전달한다. 원문 전체와 입력 해시는 유지하고,
  encoder LR1e-5, head LR3e-4, dropout0.2, 4epochs, seed1709를 사용한다. 개발 손실이 가장 낮은 epoch를 저장한다.
- `run_kg_reasoned_cascade.py`: 새 계획을 먼저 고정하고 라벨 생성·학습·개발·독립 확인·최종 평가를 순차 실행한다.
  이전 교사 라벨·학생 가중치는 재사용하지 않는다. 기존 기사 그룹 분할은 유지한다.

## 검증과 제한

실제 진단 25건과 합성 대조 16건은 공개된 개발 검사다. 참고 판정은 AI의 검토이며 사람 정답이나 모집단 정확도가 아니다.
출력 계약 v2 실행 전 고정한 개발 승인 조건과 참고 판정은 `reasoned_development/acceptance_plan.json`, `reference.json`에 있다.
확인용 41건이 잘 맞아도 전체 품질이 입증된 것은 아니다.

41건 v2는 참고 판정 일치36/41, 합성15/16, 부적절한 채택3건으로 개발 기준 미달이었다.
v3는 같은 입력·참고 판정·승인 기준으로 `reasoned_development/run_003`에서 2026-09-18 00:02:25 KST 완료됐다.
41건 중 참고 판정 일치35, 합성16/16, 부적절한 채택1, 출력 미종료1로 개발 기준 미달이다.

단순 주가 중계와 불확실한 계약 합성 사례는 고쳤지만, 스타벅스 현지 운영사 귀속 혼동은 남았다.
현대차 협력 생산·한전 요금/적자·컴캐스트 콘텐츠 계약·PayPal 현직 CFO 이동은 과도하게 제외했다.
출력 미종료는 별도 실행 실패이며 보류나 의미적 정답으로 바꾸지 않았다. 참고 판정 자체도 사람 정답은 아니다.
새 본 실험의 계획 고정과 TRAIN/DEV 전량 재판정은 아직 시작하지 않았다.
사용자에게 기존 결과 재사용 가능성을 설명했으며, 전량 재판정을 유일한 개선 방법으로 전제하지 않는다.
기존 라벨은 기존 교사의 의사라벨이며 새 교사 판정과 같은 것으로 바꾸어 기록하지 않는다.

새 본 실험 freeze/1,792쌍 전량 재판정/새 분류기 학습은 이번에 시작하지 않는다.

기존 A/B의 DEV확률을 고정50:50으로 한 번 평균하는 비교도 완료했다.
B 교사 일치163/256(63.67%), 평균156/256(60.94%); 평균logloss는0.823440으로 조금 낮지만
기존 최소20쌍·불일치2% 조건을 모든 고정 임계값에서 만족하지 못했다. 새 기준으로 채택하지 않는다.
분석 코드·입력 SHA·동일 분모·원래 routing 재현 확인은 `old_ab_equal_ensemble_dev/receipt.json`에 있다.
가중치 탐색, 라벨 변경, CAL/TEST 열람, 추가 GPU 학습은 하지 않았다.

본 실험은 학습1,536 / 개발256 / 독립 확인768 / 최종 평가512를 유지한다.
기존 최소 표본 수, 교사 불일치, 자동 처리 비율, 실제 속도 개선 조건을 낮추지 않는다.
각 fold의 실행 불가 교사 판정이 5%를 넘으면 중단한다. 학습에서는 해당 라벨만 손실에서 빼고 평가 분모는 전체를 유지한다.
개발 또는 독립 확인 단계 실패 시 다음 평가를 시작하지 않는다. 통과해도 전체 뉴스 처리 권한은 false다.

여러 개선을 함께 적용한 개발 실험이므로 어떤 변경이 개선의 원인인지 분리해 입증한 실험은 아니다.
LLM 판정과의 일치는 경제적 사실의 정답률이나 주가 예측 정확도가 아니다. 새 실제 성능은 실행 후 판단한다.

## 중단과 재개

교사 라벨은 매 기사 SQLite에 저장되며 같은 고정 입력·코드로 이어갈 수 있다.
완료 단계는 파일 해시를 확인한 뒤 재사용한다. 학생 학습은 optimizer 상태를 저장하지 않으므로
중단된 시도는 남겨두고 새 attempt에서 시작한다. 수정된 코드로 기존 실험 결과를 덮어쓰지 않는다.
