새 `kg_grounded_relations_v5.py`는 기존 v4를 보존하면서 명시적인 관계 표현을 더 처리한다. 관계의 네 종류와 공급·투자 방향은 그대로다. 뉴스 관련성 선별기 B, 뉴스 감성, GNN 가중치를 바꾸는 작업이 아니다.

추가 범위는 독립 절이 포함된 긴 문장, 명시적인 공급 고객·투자 주체·협력 상대 목록, 제한된 인접 문장의 기업 대명사, 추가 한·영 관계 표현이다. 목록에서는 문법에 명시된 역할끼리만 연결한다. 공동 고객·공동 투자자끼리의 관계를 만들지 않는다. 대명사는 바로 앞 문장에 유일한 기업 선행사가 확인될 때만 처리하며 원문 선행사와 관계절을 함께 남긴다.

사실 부정·허위 주장·미래 계획·약력·그룹/자회사 법인 혼동을 검사한다. 기존 확정 원문에 없는 상위 회사 관계를 추정하거나, 가격 동조·같은 업종을 공급·경쟁 관계로 바꾸지 않는다. B에서 빠진 상대 기업을 비시점 별칭 사전만으로 복원하지 않는다. 기존 v4의 특정 KAI 예외는 원래 증거와 정책 그대로 보존한다.

## 배치와 중단 재개

프로젝트 루트에서 `AI/ner/.venv/Scripts/python.exe -X utf8`를 사용한다.

```powershell
AI/ner/.venv/Scripts/python.exe -X utf8 AI/graph/scan_grounded_relations_v5.py `
  --baseline AI/graph/artifacts/kg_relations_v4_recent_20260919_v1 `
  --identity-revision AI/graph/artifacts/kg_grounded_relations_20260919_v2 `
  --out AI/graph/artifacts/kg_relations_v5_expanded_20260919_v1
```

출력 폴더에 `STOP` 파일을 만들면 현재 기사 트랜잭션까지 마친 뒤 중단한다. 재개 시 STOP을 제거하고 **같은 명령에 `--resume`만 추가**한다. 코드·설정·원본이 바뀌었으면 해당 체크포인트를 재사용하지 않고 새 버전 출력 폴더를 사용한다. 소스 SQLite는 읽기 전용으로 열고, 진행 상태와 신규 후보는 출력 폴더의 별도 SQLite에 저장한다.

원본·별칭·정책·코드를 SHA로 결속하고, 재개할 때 완료 기사와 후보의 체크섬·원문 위치·기업 정체성·카운터를 다시 검사한다. `manifest.json`의 완료 여부와 `eligible_scan_complete`를 함께 확인한다. 원래 B 전체 모집단에는 미처리 항목이 있으므로 이 배치 완료를 전체 원천 뉴스 처리 완료로 해석하지 않는다.

## 후보 검토와 통합

`review_relation_expansion.py prepare`는 신규 후보를 **원문 기사 전체와 함께** 검토 묶음으로 만든다. `merge`는 기존 검수 결과를 보존하고 신규 ID 전부의 `keep/review/exclude` 결정, 원문·후보 SHA, 전체 기사 검토 표시를 요구한다. 누락된 검수 항목을 자동 채택하지 않는다. AI 보조 개발 검토이며 인간 정답에 대한 정확도·재현율 평가는 아니다.

통합 시 기존 `build_integrated_relation_graph.py`에 새 관계 버전과 완전한 검토 정책을 입력한다. `endpoint_validation.extraction`에는 관계절·선행사 원문 위치와 목록의 역할 범위를 보존하므로 GraphRAG 조회에서 근거 변환 과정을 확인할 수 있다. 인접 두 문장은 연속 원문 블록으로 저장하며 별개의 문장을 임의로 이어 붙이지 않는다.

이 확장은 **문법 기반 추출의 범위 확대**다. 학습한 범용 관계 추출 모델로 대체한 것이 아니며, 관계 개수 증가만으로 품질·주가 예측력 향상을 주장하지 않는다. 기존 서비스·HDFS·모델 번들의 교체는 별도다.
