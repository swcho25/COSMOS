# 기존 뉴스 품질 export 240건 블라인드 의미 검토

검토일: 2026-09-16. **AI 보조 의미 검토 240건 완료, 사람 검토 완료 0건.** 사람 정답셋이나 GNN 성능 평가가 아니다.

자동 채택 표본 120건에서 현재 연결기업 사건이 뒷받침된 것은 77건, 뒷받침되지 않은 것은 27건, 보류는 16건이었다. 자동 제외 표본 120건에서는 각각 45건, 63건, 12건이었다. 채택에도 잘못 귀속된 사건이 남고, 제외에도 유효한 사건이 존재한다는 **이번 표본의 관찰**이다. 균등 층화 표본을 합친 건수이며 전체 데이터의 precision·recall로 해석하지 않는다.

## 대상과 블라인드 절차

- 모집 프레임은 기존 `news_quality_source_20260915/training_candidates.jsonl`의 54,683건이다. 기존 v2 자동 채택 28,026건, 제외 26,657건의 소속을 이용해 추출했다. 약 1,326만 원천 행 전체나 새 규모 실험 데이터에 대한 대표 표본이 아니다.
- 국내/해외 × 2017–2022년 × 기존 자동 채택/제외의 24개 층에서 각각 10건을 추출했다. 목표 240건을 모두 확보했고 부족한 층은 없다.
- `SHA256("scale-semantic-review-20260916-v1:" + record_id)`가 낮은 순서로 선택하고, 별도 `blind-order` 해시로 제시 순서를 섞었다. 기사별 가격·수익률·학습 라벨·모델 예측은 선택에 사용하지 않았다.
- 기존 record_id 기반 검토 108건을 우선 제외했다. 과거 target audit의 숫자 article 인덱스로 남은 100건도 원래 기사 ID로 복원했다. 두 집합은 겹치지 않으며, 총 208건과 이번 240건의 중복은 0이다. 전체 208건을 제외하여 재생성한 `repro_check/blind_packet.json`은 처음 패킷과 **바이트 단위로 동일**하다.
- 패킷은 제목, 날짜, 출처, 원문 전체, 기존 정제 함수를 변경 없이 적용한 본문, 원래 연결된 티커·회사명을 제공했다. 제외 파일의 잘린 본문도 원본 export에서 복원했다. 자동 채택/제외, 제외 사유, 자동 이벤트 근거, 메타데이터 라벨은 숨겼다.
- 현재 회사 사전의 이름을 설명용으로 제공했으므로, 과거 법인·그룹 귀속을 인증한 것은 아니다.
- 1–160 / 161–200 / 201–220 / 221–240을 네 AI 담당자가 나눠 실제 문맥을 읽었다. 독립된 사람의 이중 검토나 평가자 간 일치도 측정은 하지 않았다.
- 236건은 원문·정제본 전체를 확인했다. 4건은 전체 정제본과 **생략 없는** 원문 변경 영역을 읽어 원문 내용도 모두 확인했다. 일시적으로 원문 변경부를 제한 열람했던 68·77·123번은 전체 원문 재열람 후 판정 변화 없이 범위 기록을 보완했다. 이 과정은 별도 addendum에 남았다.
- 240개 판정의 ID·인용문·연결 티커와 입력 파일 SHA256을 검증한 뒤 `blind_verdict_freeze.json`에 판정 파일 해시를 고정했다. 그 뒤 처음 자동 소속을 공개해 층별 집계했다. 의미 판정에 정규식이나 기존 자동 판정을 재사용하지 않았다.

별도 가격·미래성과·모델 예측 데이터는 열람하지 않았다. 다만 **보존된 원문 자체에 후대 뉴스, 시세 위젯, 발행사의 AI 종목 영향 문구가 들어 있는 사례가 있었다.** 이 부분은 오염으로 취급했으며 현재 사건이나 가격 결과의 근거로 사용하지 않았다. 원문에 그런 정보가 전혀 없었다는 주장은 하지 않는다.

## 판정 기준

기사 단위로 원래 연결된 기업 중 하나 이상에 대해 현재의 구체적 재무·기업 운영 사건이 명시되면 `supported`로 판정했다. 실적·계량된 현재 실적 전망, 계약·수주, 생산·서비스 변경, 제품 출시·리콜, 지배구조·인사, 직접적인 법률 사건 등을 포함한다. 기사에 있는 사건이 주가를 예측할 수 있다는 뜻은 아니다.

다른 기업이 사건 주체이고 연결기업은 비교 대상·과거 제휴사·분석가 고용주인 경우, 과거 사례나 단순 주가·추천·발표 일정만 있는 경우, 재무·운영 변화 없는 CSR 행사만 있는 경우는 `unsupported`다. 회사 실체·발생 시점·사건 구체성이 본문만으로 불명확하면 `uncertain`으로 남겼다. 지주와 은행, 그룹과 상장 자회사에 사건을 자동 전파하지 않았다. 기사 전체가 supported여도 모든 연결기업이 올바르다는 뜻은 아니며 `supported_tickers`와 사유로 구분했다.

`entity_correctness`, `feed_contamination`, `historical_background`도 별도로 남겼다. 특히 `feed_contamination=present`는 무관한 추천 피드뿐 아니라 광고·구독/차트 UI·의도적인 다중 기사 요약까지 포함한 **넓은 보조 표시**다. 이 합계를 악성 크롤링 오염률이나 정제 후 잔존 오염률로 사용하면 안 된다. 사유에서 종류와 제거 여부를 구분한다.

## 확인한 것과 아직 가설인 것

**확인한 것:** 이 표본에는 채택된 잘못된 기업 귀속과 제외된 구체적 기업 사건이 모두 있다. 과거 배경, 분석가 소속, 후대 추천 피드, 은행/지주 및 그룹/상장법인 구분이 실제 검토 쟁점이다. 현재 자동 채택 여부를 의미적 정답으로 그대로 사용할 수 없다.

**아직 검증할 가설:** 표본 확대, 현재 사건의 기업 귀속 개선, 뉴스 표현 개선, 당시 유효했던 기업 관계의 복원이 GNN 성능을 올릴지는 이 검토로 알 수 없다. 기사 내용의 의미적 타당성과 향후 가격 예측력은 다른 문제다. 같은 전처리·분할·모델·시드 조건의 2만/5만/10만 비교를 별도 결과로 판단해야 한다.

각 층 10건이고 균등 할당이므로 작은 차이를 지역·연도의 안정적 품질 차이라고 결론내리지 않는다. 77/120 같은 단순 합산 비율을 전체 채택 데이터의 precision으로 부르지 않으며, 제외 표본의 supported 건수로 전체 recall을 계산하지 않는다. 사람 검토와 표본 설계에 맞는 추정이 별도로 필요하다.

이제 결과를 공개한 240건은 후속 규칙을 평가할 미사용 정답셋이 아니다. 추후 규칙을 개선한다면 개발용 사례와 새로운 블라인드 평가 표본을 분리하고, 모델의 최종 성능은 아직 쓰지 않은 후속 기간에서 검증해야 한다. 특정 확률 임계값에서 정확도가 65%여도 선택된 예측의 비율(coverage), 표본 수, 전체 클래스 성능과 함께 보고해야 한다. 이번 검토로 65% 성능이나 임계값의 유효성을 주장하지 않는다.

## 산출물과 재현

코드: `sample_scale_review.py`. 산출물 디렉터리: `artifacts/news_scale_review_20260916/`.

- `blind_packet.json`, `batch_01.json`–`batch_24.json`: 동일한 240건, 원문·정제본·연결기업 포함.
- `protocol.json`: 최초 추출 조건·입력 해시. 초기 코드 해시는 당시 패킷 생성 버전이다.
- `verdicts_*.json`: 각 담당자의 블라인드 판정·정확한 인용·사유·열람 범위.
- `blind_freeze_001_160*.json`: 1–160의 최초 고정과 원문 전체 재열람 범위 보완 기록. 의미 판정은 변경되지 않았다.
- `blind_verdict_freeze.json`: 240건 전체 판정 고정 시각·해시와 최종 검토 코드 해시. 집계는 이 해시가 유지될 때만 실행된다.
- `ai_review.json`: 240건 통합 판정. `human_gold=false`, `human_review_completed=0`.
- `sealed_selection.json`: 자동 소속 매핑. 판정 고정 후 집계 때 공개했다. 암호화나 접근 제어가 있는 봉인이 아니라 절차적 블라인드다.
- `summary.json`: 24개 층의 건수, 보조 항목, 미확보 층 0, 모집단 precision·recall은 null.
- `reproducibility_audit.json`, `repro_check/`: 기존 검토 208건 모두 제외한 재생성의 패킷 SHA256 동일성 기록.

저장된 판정을 검증하고 같은 집계를 재현하는 명령:

```powershell
AI/ner/.venv/Scripts/python.exe AI/graph/sample_scale_review.py --stage validate
AI/ner/.venv/Scripts/python.exe AI/graph/sample_scale_review.py --stage finalize
```

새 경로에 패킷을 다시 생성하려면 `--stage prepare --out <새 디렉터리>`를 사용한다. 새 의미 판정은 사람이든 AI든 실제 문맥을 다시 읽어 별도로 작성해야 하며, 스크립트는 의미 정답을 자동 생성하지 않는다. `freeze`는 전체 판정이 완비되어야 실행되고 이미 있는 고정 기록을 덮어쓰지 않는다. 이번 작업에서는 학습·원격 조회·기존 파일 변경을 하지 않았다.
