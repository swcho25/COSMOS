# LLM 판정 증류·선택적 재검토 실험

현재 목적은 뉴스×기업의 **경제 관련성 채택·제외·보류 판정**을 더 빠르게 얻는 것이다.
LLM과 같은 판정을 내는지와 실제 시간을 줄이는지를 따로 검증한다.
LLM 판정 자체가 틀릴 수 있으므로 일치율을 사람 정답 기준 정확도로 쓰지 않는다.
이 실험은 기업 관계·원문 근거 추출, 완성된 지식그래프 생성, GNN 재학습과 구분한다.

## 이번 변경

- 전체 후보 추출 결과에서 기존 검토 기사 750개와 가격 검증·시험 기사 11,969개를 제외한다.
- ID·정규화 URL·본문으로 전체 후보의 중복 그룹을 먼저 만든다. 같은 그룹을 다른 분할에 넣지 않는다.
- 새 기사 그룹 3,072개에서 기업 하나씩 선택한다. train 1,536 / dev 256 / calibration 768 / test 512.
- 이전 금융 키워드로 제한한 189,101건을 모집단으로 쓰지 않는다. 이 파일은 제외 기사 신원 복원에만 사용한다.
- 기존 고정 Qwen으로 판정 자료를 만들고 MiniLM의 본문 인코더와 분류 헤드를 함께 학습한다.
- 기업명이 모든 본문 창에 들어가며 전체 토큰을 처리한다. 긴 원문을 앞부분만 잘라 판정하지 않는다.
- DEV에서 모델과 임계값을 정한 뒤 CAL에서는 그 임계값을 통과/탈락만 판정한다. TEST 결과로 설정을 다시 고르지 않는다.
- 통과한 채택/제외 구간만 학생 모델을 사용한다. 보류·처리 실패·자동 판정 구간 밖은 Qwen으로 보낸다.

학습 설정: encoder LR 2e-5, head LR 1e-3, 3 epochs, seed 1709, gradient accumulation 8 articles,
window microbatch 4, window length 256 tokens, 최대 64 windows. 최대치를 넘으면 명시적으로 fallback한다.
기존 80건으로 고정 인코더의 선형 분류기만 학습했던 실험과 구분한다.

## 통과 조건과 해석

CAL의 각 자동 판정 방향은 서로 다른 기사 그룹 최소 183개로 확인한다.
고정 임계값의 교사 일치율에 대해 97.5% 단측 정확 이항 신뢰하한 98% 이상을 요구한다.
표본 수 부족이나 불일치가 많으면 해당 방향을 비활성화한다. CAL에서 다른 임계값을 다시 찾지 않는다.

봉인된 TEST 512개에서는 전체 추가 불일치의 95% 단측 상한 2% 이하,
자동 처리 비율 30% 이상, 실제 판정 파이프라인 시간 단축을 함께 확인한다.
모든 기사를 LLM으로 넘겨 판정이 같아지는 것은 가속 성공이 아니다.
fallback을 실제 재실행해 교사 판정 변화도 확인한다. 기준 실행이 중단 후 재개되었다면
그 실행의 총 시간으로 속도 향상을 주장하지 않는다.

시간은 모델 로드와 파일 입출력을 포함한 순차 프로세스 실측이다. 기준은 SQLite 재개 worker,
fallback 재실행은 배치 CLI를 사용하므로 각 방식의 운영 비용도 포함된다.
초기 교사 자료 생성·모델 학습 비용과 이후 그래프 근거 추출 비용은 추론 시간과 별도로 봐야 한다.
학생이 내놓는 확률값은 사실적 정확도의 확률이 아니다.

그룹당 하나를 뽑는 실험이므로 기사×기업 2,656,806행 전체의 정확도를 보증하지 않는다.
동일 사건을 다르게 쓴 기사까지 모두 중복으로 찾은 것도 아니다.
교사와 학생이 함께 틀리는 문제는 별도의 독립 검토가 필요하며, 이 작업은 별도 후속 검토로 남긴다.

학생의 빠른 판정에는 정확 인용문이나 직접/간접 관계 유형이 없다.
`graph_materialization_ready=false`, `relation=null`로 유지한다.
그래프에 사용할 검증된 근거가 필요한 요청은 별도 추출·검증 또는 LLM 단계가 필요하다.

## 실행과 재개

실험 폴더: `artifacts/kg_cascade_v1_20260917_v1`.
계획과 코드 해시는 새 표본·교사 판정을 보기 전에 고정한다.

```powershell
& AI/ner/.venv/Scripts/python.exe -X utf8 AI/graph/run_kg_cascade_pilot.py `
  --mode run --out AI/graph/artifacts/kg_cascade_v1_20260917_v1
```

이 명령은 서버의 승인된 후보 추출 완료를 기다린 뒤 로컬로 검증·다운로드하고
표본 준비 → 교사 train/dev 판정 → 학생 학습 → DEV 임계값 고정 → CAL 확인 → TEST 비교를 순서대로 실행한다.
전량 2,656,806쌍을 LLM에 보내는 명령은 실행하지 않는다.
전송 스크립트의 `--download-only`가 전체 worker 자동 실행을 막는다.

`status.json`의 stage, `stages/*.json`, `logs/*.log`로 상태를 확인한다.
추출 대기 중에는 `transfer/transfer_status.json`, 표본 준비 중에는 `samples/attempt_*/status.json`,
교사 판정 중에는 `teacher_*/status.json`, 학습 중에는 `student_training/attempt_*/epochs.jsonl`도 확인한다.
최종 결과는 `evaluation_report.json`이며 `PILOT_COMPLETE`가 품질 통과를 의미하지는 않는다.

PC를 끄면 **로컬** 다운로드·LLM·학습 작업은 멈춘다. 서버 Spark/과거 정제 작업은 독립적으로 계속된다.
같은 명령을 다시 실행하면 완료 단계는 해시를 확인하고 재사용하며 교사 추론은 커밋된 청크부터 이어간다.
중단된 학습·표본 준비·예측 시도는 보존하고 새 attempt에서 시작한다.
실험 중 고정한 코드·정책·모델을 수정하면 혼합 실행을 막기 위해 정지한다.

서비스·기존 HDFS 분석 결과·DB·GNN 번들을 변경하지 않으며 자동 게시하지 않는다.
모델과 대용량 결과는 기존 `artifacts/`, `local_models/` Git 제외 경로에 둔다.

## 실행 검증

RTX4050 6GB에서 가상 train 6개/dev 3개로 1 epoch 학습·저장·두 번 재로딩을 검사했다.
10개 창, 2,398/2,413 본문 토큰을 전부 처리했고 인코더 197개 텐서에 유한한 gradient가 생겼다.
확인한 인코더 텐서 62개 모두 값이 바뀌었으며 재로딩 전후 확률이 정확히 같았다.
최대 할당 VRAM 2.20GiB, 예약 2.45GiB, 검사 전체 27.34초.
이는 실행·메모리 검증이며 **실제 뉴스 선별 성능 검증이 아니다**. 최대 64개 창의 VRAM 실측은 아니다.
원본 번들과 교사 모델은 보존했다. 자세한 기록은 `artifacts/kg_cascade_gpu_smoke_20260917_v1/smoke_receipt.json`.
