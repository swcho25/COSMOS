# 선별 뉴스의 근거 기반 로컬 지식그래프

기존 B 선별 결과에서 저장·검증된 채택 후보 **666,282 기사–기업 쌍 / 483,738 기사**를 입력으로 사용한다. B 선별 품질 검증을 통과했다는 의미는 아니다. 원래 B 결과를 수정하지 않고, 각 연결에 근거를 붙일 수 있는지 별도로 검사한다. 원래 중단된 PC1 선별 작업과 미처리 142,361쌍은 그대로 둔다.

## 생성 과정

1. 원문·선별 결과의 해시를 확인하고, 알려진 주가 위젯·추천 뉴스 구간을 정제한다.
2. 뉴스–기업별로 이름 충돌, 단순 경력·애널리스트 소속, 다른 기업 사건, 날짜와 확인 가능한 과거 명칭을 검사한다. 근거가 있는 후보는 `candidate_ready`, 명확한 제외는 `exclude`, 판단하기 어려운 것은 `review`로 저장한다. 모두 B의 원래 `include`와 별개인 후속 처리 상태다.
3. 같은 기사에서 두 기업이 모두 근거를 확보한 경우, 명시적인 공급·협력·경쟁·투자·인수 문장에 한해 관계를 추출한다. 함께 등장했다는 사실만으로 관계선을 만들지 않는다.
4. 대상 기업의 근거 문맥에 로컬 한국어·영어 FinBERT를 적용한다. 다른 기업이 섞였거나 상반된 감성, 언어 불명, 입력 길이 초과이면 감성은 `NULL`이다.
5. SQLite에 묶음별로 저장하고, 범위·참조·원문 인용·출력 해시를 확인해 JSONL을 내보낸다.

`candidate_ready`는 기사에 경제적 사건의 후보 근거가 있다는 뜻이다. 실제 주가 영향, 사람의 정답, 서비스 배포 승인이나 GNN 학습 준비 완료를 뜻하지 않는다. 현재의 금융 감성 모델은 기업별로 따로 학습된 측면 감성 모델이 아니므로, **기업을 구분한 근거 문맥의 금융 감성**으로 해석한다. 모델 확률도 정답률이 아니다.

## 산출물 계약

### 서비스에서 완성해야 하는 기능

기업 관계의 공개 분류는 공급(`SUPPLY`)·투자/지분(`INVEST`)·협력(`PARTNER`)·경쟁(`COMPETE`) 네 가지다. 관계별로 원문 근거 뉴스와 URL·발행 시각을 연결하고, GraphRAG가 해당 관계의 근거를 검색해 출처가 있는 설명을 반환해야 한다. 하나의 기업 쌍에 여러 관계가 존재할 수 있으며, 네 종류를 모든 기사에서 강제로 만들지는 않는다.

뉴스–기업별 분석 결과는 긍정(`POSITIVE`)·부정(`NEGATIVE`)·중립(`NEUTRAL`)이다. 분석 보류는 감성 종류가 아니며 `status`와 `label=null`로 구분한다. 현재 결과는 근거 문맥의 금융 감성이다. GNN의 주가 영향 방향·강도 예측과는 별도의 출력이다.

초기 로컬 산출물 이후 `kg_grounded_relations_v2.py`로 공개 네 종류와 투자·지분/경쟁 표현을 보완했고, `grounded_relation_graphrag.py`로 새 관계 수정본의 뉴스 검색·설명을 연결했다. 사용법은 `README_RELATION_GRAPHRAG.md`를 따른다. 기존 `news_graphrag.py` 설명 기능이 이번 파일들을 자동으로 읽는 것은 아니다. 로컬 기능 검증과 관계 추출 품질·운영 화면 연결 완료는 구분한다.

완료한 실행의 `manifest.json`에 기록된 파일 경로만 소비한다. 중간 `exports/attempt_*` 폴더가 존재하는 것만으로 완료로 판단하지 않는다.

| 파일 | 내용 |
| --- | --- |
| `selection_audit.jsonl` | 입력 쌍별 후속 판정, 사유, 원문 근거, B 결과 해시 |
| `news_nodes.jsonl` | 채택 가능한 연결이 하나 이상 있는 뉴스, 원문·정제문·URL·발행 시각 |
| `company_nodes.jsonl` | 연결에 등장하는 기업 ID와 현행 사전 표시명 |
| `news_company_edges.jsonl` | 뉴스→기업, 정확한 근거 위치, 관련성 후보 사유, 감성 결과·보류 상태 |
| `relationship_evidence.jsonl` | 기업→기업 관계 유형·방향, 기사 ID·URL·정확한 근거 문장 |
| `company_relationships.jsonl` | 기업 쌍·관계 유형별 근거와 기사 수 |
| `relation_review.jsonl` | 단정하지 못한 기업 간 관계 후보 |

근거 `quote`는 원래 입력의 정확한 부분 문자열이고 `cleaned_quote`는 모델용 정제 문맥이다. 두 필드를 혼동해서 인용하지 않는다. 관계 문장 위치는 **원문 제목 + 줄바꿈 + 원문 본문** 기준이다. 발행 시각을 사건 발생 시각으로 사용하지 않는다. 시각의 시간대가 미확인이라면 그대로 표시한다. 현행 기업 사전은 과거 법인·사업·계열 관계의 증명이 아니다.

여기서는 감성 결과와 관계의 근거를 만들며, 7D·30D·90D 관계 점수 재집계, HDFS 적재, 서비스 DB 갱신, GNN 재학습은 수행하지 않는다. 새로운 데이터의 품질과 시점 정보를 검증한 뒤 별도 단계로 진행한다.

## 실행과 중단·재개

저장소 루트의 PowerShell:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File AI/graph/start_grounded_kg.ps1
AI/ner/.venv/Scripts/python.exe -X utf8 AI/graph/read_grounded_kg_progress.py
```

다음 파일을 만들면 현재 묶음 저장 후 멈춘다. 원래 B 선별기의 STOP 파일과는 별개다.

```powershell
New-Item -ItemType File -Path AI/graph/artifacts/kg_grounded_full_20260918_v1/STOP -Force
```

`status.json`이 `paused_stop_file`이고 프로세스가 종료된 뒤 컴퓨터를 끈다. 전원이 갑자기 꺼져도 SQLite에 커밋된 묶음은 유지되며 미완료 묶음부터 재처리한다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File AI/graph/start_grounded_kg.ps1 -Resume
```

재개할 때 입력, 실행 코드, 사전, 모델·토크나이저 파일과 설정이 같아야 한다. 변경했다면 새 출력 폴더를 사용한다. Windows 샌드박스에서는 다중 프로세스 통신이 차단될 수 있으므로 로컬 실행 권한이 필요할 수 있다. 외부 API나 다운로드는 사용하지 않는다.

상태·로그·모델·출력은 기존 Git 제외 경로인 `AI/graph/artifacts/`에 저장한다. 자동 알림·예약 작업은 만들지 않는다.

Windows에서 실행 중인 `status.json`을 `Get-Content` 등으로 잠그면 빠른 원자적 파일 교체와 충돌할 수 있다. 실행 중에는 위 읽기 전용 SQLite 조회기를 사용한다. 저장된 커서만으로 실행 중임을 단정하지 말고, `*.launcher.json`의 PID와 로그도 확인한다.
