## 확인한 문제

첫 학생 분류기는 1,536쌍으로 학습하고 256쌍으로 개발 검증했으나,
고정된 자동 판정 기준을 충족하는 개발 사례가 없었다.
학습 `review` 539쌍에는 인용 번호 누락 345쌍과 직접/간접 유형 불일치 99쌍이 섞여 있었다.
이들은 모두 경제적 관련성이 불명확하다는 뜻이 아니다.
또한 기존 Qwen은 가격·거래량만 있는 기사나 다른 기업의 문장을 잘못 채택하는 오류도 보였다.
상세 진단은 새 작업 폴더의 `audit/diagnosis.md`에 있다.

2026-09-17 15:54~15:58 KST 확인 시 원본 coordinator와 Python 자식 프로세스는 없었고 GPU는 비어 있었다.
상태 파일에는 `RUNNING`이 남아 있었지만 실제 실행을 뜻하지 않았다.
최근 조회한 Windows 충돌/메모리 부족 기록에 관련 항목은 없었다. 종료 원인은 확인되지 않았다.
자동 방향이 하나도 없는 원본 실험의 후속 검증을 그대로 재시작하지 않는다.

## 수정 범위

- `kg_semantic_teacher.py`: 같은 로컬 Qwen을 사용하되 경제적 관련성 분류만 요청한다.
  전체 기사와 대상 기업을 두 프롬프트로 각각 제시하며 첫 답을 두 번째에 보여주지 않는다.
  직접/간접은 모두 채택 후보로 합치고, 분명한 무관/단순언급은 제외, 의미상 불명확/불일치는 보류한다.
  제한된 한 토큰 출력은 인용 ID 생성 실패와 경제적 불명확성을 분리한다.
  본문 초과·메모리 오류는 별도 실행 불가이며 자동 제외하지 않는다.
  두 종류의 관측된 시세 자동기사 전체 형식이 일치할 때만 별도 규칙으로 제외한다.
  추가 사업 사건 문장이 있으면 이 규칙을 적용하지 않는다. Qwen 원답과 규칙 적용 결과는 모두 보존한다.
  Qwen이 제외하더라도 대상 기업의 문자상 이름을 확인하지 못하면 보류한다.
  이 보류 규칙은 과거 사명·모자회사·번역명을 복원하거나 관련성을 입증하지 않는다.
- `kg_cascade_student_v2.py`: 전체 토큰을 보존하는 후보 A와 B를 비교한다.
  A는 문서 표현 뒤 LayerNorm/MLP, B는 기업·본문 표현 및 기업을 고려한 창별 attention을 사용한다.
  4 epochs, encoder LR 2e-5, head LR 3e-4, seed 1709를 사전에 고정한다.
- `kg_cascade_semantic_labels.py`: 과거 결과의 진단용 해석기다. 새 교사 정답이나 운영 선별기로 승격하지 않는다.
- `kg_cascade_bulk.py`: 검증 통과 기록에 묶인 모델/규칙만 전체 후보에 적용한다.
  SQLite에 진행 위치와 판정을 함께 저장하며, 애매한 입력은 별도의 대기 목록에 남긴다.
  소요 시간은 모델 준비 비용을 한 번만 더하고 기사 추론 비용을 전체 건수로 환산한다.

두 번의 판정은 같은 모델의 서로 다른 프롬프트다. 독립된 사람 정답이 아니다.
새 교사와의 일치를 과거 인용 검증까지 포함한 결과와 동등한 성능이라고 말하지 않는다.
첫 개발 검사에서 가상 8사례 중 2개 판정 차이 및 실제 LG화학 시세 기사 오채택이 발견되어
개발 프롬프트를 보완했다. 이 개발 사례는 최종 정확도 표본이 아니다.

## 평가와 전체 처리의 의미

같은 원본 분할(학습 1,536 / 개발 256 / 독립 확인 768 / 최종 평가 512)을 사용한다.
개발 단계만 모델과 임계값 선택에 사용한다. 독립 확인·최종 평가를 보고 기준을 낮추지 않는다.
자동 방향을 확인하지 못하면 품질 미달로 기록하고, 효과가 없는 전체 실행을 시작하지 않는다.

전체 빠른 판정을 한 번 수행하는 것과 모든 기사의 최종 판정이 끝나는 것은 다르다.
`include`, `exclude`, `needs_review`를 모두 계수하며 대기 목록을 제외로 바꾸지 않는다.
채택 후보에는 원문 인용이나 기업 간 관계 유형이 아직 없다. 별도 추출·검증이 있어야 지식그래프로 만들 수 있다.
실제 주가 영향, GNN 학습 적합성, 기존 GNN 성능 개선 역시 별도로 검증해야 한다.

## 기업 화면의 긍정·부정·중립 — 후속 지식그래프 산출물

2026-09-17 사용자 요청으로 후속 범위를 명시한다. 현재 경제 관련성 선별기는 감성을 출력하지 않는다.
채택한 뉴스→기업 연결마다 해당 기업 관점의 감성, 원문 근거, 판정 상태와 모델 버전을 만들어야 한다.
예를 들어 한 기사가 삼성전자 매출 증가와 애플 매출 감소를 함께 설명하면 기업별 값이 달라질 수 있다.
관련성 점수, 기사 감성, GNN의 미래 가격 방향 예측은 각각 별도의 필드다.

기존 `lake_sentiment.py`는 제목과 본문 첫 200자에서 기사 단위 감성을 계산한다.
현재 이 값을 언급 기업들에 결합하는 방식만으로는 기업별 감성 품질을 입증할 수 없다.
전체 원문에서 해당 기업 사건·근거를 판정하는 후속 구현과 별도 검증이 필요하다.
미분석·근거 부족·실행 실패는 `sentiment = NULL`과 별도 상태로 남긴다. 중립으로 채우지 않는다.
긍정·부정 정보가 혼재하여 단일 방향을 정할 수 없는 경우도 보류 정책을 별도로 정해야 한다.

DB의 `company_document`는 `(document_id, company_id)`별 nullable `sentiment`를 이미 가진다.
추가 산출물 계약 후보는 `document_id`, `company_id`, `sentiment`, `sentiment_status`,
`evidence_refs`, `model_version`, `analyzed_at`이며, 보정하지 않은 모델 점수를 정확도나 신뢰확률로 표시하지 않는다.
Loader 적재, 선택 기업 기준 조회·필터, 미분석 배지는 BE/FE와 함께 연결해야 한다.
로컬 FE는 감성 누락을 중립으로 표시하지만 사용자 화면은 '분석 전'을 표시해 버전 차이가 있다.
배포 API/DB의 실제 원인은 아직 확인하지 않았다. 이 문서 추가는 감성 구현·서비스 연결 완료를 뜻하지 않는다.
